# LearnHive notification service
Сервис предназначен для упрощения приёма и передачи задач в проекте путем уведомления разработчика/ревьюера 
о проверке/поступлении Merge Reqeust'а 
## 1. Цель

Документ описывает процесс приёма и передачи задач в проекте, включая этапы проверки, внесения исправлений и мержинга кода.

## 2. Процесс работы

1. **Разработчик** отправляет код в GitLab.
2. Разработчик создаёт **Merge Request (MR)**.
3. Разработчик отправляет ссылку на MR **проверяющему**.
4. **Проверяющий** открывает MR и проверяет код.
5. Если есть замечания, проверяющий оставляет комментарии.
6. Разработчик исправляет код, пушит изменения и повторно отправляет ссылку на MR.
7. Проверяющий повторно проверяет код. Если есть замечания, процесс повторяется с шага 6.
8. После одобрения проверяющий мержит код в основную ветку.

## 2.1 Типы пользователей

- **Разработчик** – пишет код, отправляет его на проверку, исправляет ошибки.
- **Проверяющий (ревьюер)** – проверяет код, оставляет комментарии, одобряет или отклоняет изменения.

## 2.2 Статусы проверки

- 🟡 **"На проверке"** – присваивается при создании MR.
- 🔴 **"Исправить"** – присваивается, если есть замечания.
- ✅ **"Закрыто"** – присваивается после успешного мержинга. Проверяющий оставляет комментарий _"Done"_.
